# 开发模式诊断中心计划

## 当前状态与目标

- 阶段：实现完成，待真实桌面验收。
- 目标：在 Vite 开发模式提供一个诊断中心，分别开启或关闭性能监测与 Agent 流程追踪；按一次请求查看结构化步骤、状态与耗时，用于定位路由、模型、工具和结束阶段的等待或失败。
- 非目标：不改变 Agent 决策、工具权限、对话展示或生产版行为；不新增数据库表、正式设置项或持久化诊断历史。
- 当前工作区已有 `src-tauri/target-reading-position-baseline/` 未跟踪目录，视为用户现有内容，不纳入本任务。

## 本次实现结果

- 已新增开发模式 Agent Trace 收集器与有界内存 Store；模型请求、实际工具执行、路由元数据、结束原因和耗时均以脱敏结构化字段记录。
- 已将原性能面板扩展为统一「开发诊断」入口，展开后提供「设置 / 性能检测 / Agent 检测」三 Tab；性能和 Agent 检测均默认关闭且可分别开关。收缩态在两项都关闭时保留图标，开启哪项就显示哪项的关键数据，两项同时开启时并排显示。
- 已补充性能追踪器的对称卸载，处理 Timer、RAF、EventTarget、Observer、Object URL、FPS 和 long-task 监听的恢复。
- 已补充 `tests/agent/devAgentDiagnostics.test.ts`，验证关闭不创建 Trace、Span 正常计时和超时收束。
- 机器验证：性能/Agent 定向 3 个测试文件、12 个用例通过；`npm run typecheck`、`npm run lint`（仅既有 warning）、`npm run build:desktop` 与 desktop bundle budget 通过。
- 待验证：真实开发版桌面中分别开关性能/Agent，执行直答、单工具、并行工具、取消/超时、连续两轮及 Agent JSON 导出；确认无敏感文本、路径和凭据。

## 已核实的实现边界

- `App.tsx` 只在开发模式懒加载 `PerfMonitorPanel`；`usePerfMonitor` 挂载后开始采样，现有面板默认收起。
- 性能采样由 `perfCollector`、`perfStore` 和 `runtimeResourceTracker` 承担。`perfCollector.dispose()` 只停止采样；资源追踪器安装的 Timer、RAF、事件监听、Observer、Object URL 包装目前没有卸载入口。因此关闭性能检测不能仅隐藏面板或暂停样本。
- 一次对话的入口在 `useAiChat.ts`，路由只计算一次；`executor.ts` 负责模型循环和工具执行。现有 `AgentStep` / `decodeAgentStepEvent` 供聊天进度使用，其 `Date.now()` 时间戳及 `action`、`observation` 事件不足以准确表示模型等待、并行工具的各自耗时与整轮时长。
- 普通读取工具可能并行，选区读取按层级串行，写入有单次限制；不能靠相邻步骤时间差推算工具耗时。
- 性能报告 schema v2 和旧报告迁移保持原样。Agent 诊断作为独立的内存记录与单独导出，不混入既有性能报告格式。

## 设计决定

1. **一个入口、两个独立开关。** 保留右下角开发工具入口；两项都关闭时收缩态只显示图标，开启性能或 Agent 后显示对应关键数据，两项同时开启时并排显示。展开后固定提供「设置 / 性能检测 / Agent 检测」三 Tab。两个检测默认关闭，只在本次页面会话内生效，刷新后重置。关闭时停止对应采集和订阅，清空或保留已采集记录由界面“清空”操作单独控制，避免误删调试证据。
2. **按请求记录有界 Trace。** 每轮用 `runId` 关联路由、上下文准备、长期记忆预检、Agent 迭代、模型请求、工具批次/单个工具、结果结束。记录 `spanId`、父级、阶段名、开始/结束的 `performance.now()`、耗时、结果码和少量白名单元数据；并发 Span 允许时间重叠。展示整轮墙钟耗时及各阶段耗时，不将重叠时间相加冒充总耗时。
3. **区分进度与诊断。** 聊天现有 `AgentStep` 不改语义，不把原始步骤 `content`、`toolArgs`、模型响应、文档内容、路径、API Key 或错误原文复制到诊断日志。诊断只记录路由原因码、阶段/工具名称、序号、执行/复用/跳过、成功/失败/取消/超时等结构化字段；错误使用受控分类码。
4. **开发模式隔离。** 诊断入口和采集模块仅由 `import.meta.env.DEV` 路径装载；关闭 Agent 开关时请求路径只做廉价启用判断，绝不影响执行结果。生产构建不得安装性能包装、计时订阅或 Agent Trace 收集器。
5. **受控内存与导出。** 为 Agent Trace 设固定请求数和事件数上限；可按单轮筛选、查看阶段树/时间线、清空、导出脱敏 JSON。导出只在用户点击后生成 Object URL，并在完成后释放。导出包含 schema 版本和相对耗时，不包含原始聊天数据。

## 实施阶段与验收

### 1. 统一入口与性能开关

- 将现有性能面板放入开发诊断中心，保留现有概览、进程、资源、文档负载、事件、频率和导出操作。
- 将 `usePerfMonitor` 的安装、订阅和采样置于独立开关控制下；为 `runtimeResourceTracker` 补对称卸载，恢复原生 API，断开 Observer/监听并停止 RAF/长任务采样。处理 React StrictMode 重挂载和快速开关，保证不会双重包装或留下旧回调。
- 验收：性能关闭时无周期 Rust `get_perf_snapshot` 调用，原生 API 引用恢复；重新开启后只安装一套追踪器，现有面板功能仍可用。

### 2. Agent 结构化计时

- 在 `useAiChat` 请求边界和 `executor` 的模型/工具执行边界发出开发模式诊断事件，使用与当前请求绑定的 `runId`，确保取消、超时、异常、后续请求和迟到结果都能正确收尾或丢弃。
- 单个工具在实际执行处计时，标识复用缓存、预算跳过、拒绝等结果；只把结构化元数据送到诊断收集器，避免序列化参数或结果。
- 验收：直答显示路由结果；Agent 显示每轮模型等待、每个工具及总耗时；并行工具各自有时长；取消、失败、超时不会留下永远运行的 Span，也不会串到下一轮。

### 3. Agent 视图与导出

- 在同一入口展示最近请求列表、阶段树或时间线、总耗时、各步骤耗时与结束原因；只呈现适合调试的结构化字段。性能和 Agent 开关互不影响。
- 验收：仅开启其中一个时另一个没有采集；关闭后停止新增记录；上限生效；导出 JSON 无文本、路径、凭据与原始错误信息。

### 4. 定向验证

- 先执行相关 Agent/性能单测及 `npm run typecheck`、`npm run lint`，再执行 `npm run build:desktop` 和对应 bundle 门禁；只在修改共享 Web 入口或能力边界时补 Web 构建。
- 用开发版桌面实际走直答、单工具、并行工具、失败/超时、取消、连续两轮和开关切换；核对 Trace 的时序、耗时与无敏感内容。机器检查通过不等于桌面操作已验收。
- 若修改涉及 `App.tsx` 启动路径，实施前记录同机首屏基线，确保诊断中心没有阻塞真实首屏；若引入性能敏感启动改动，再按项目规定做新鲜 Release 冷启动对照。
